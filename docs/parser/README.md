# The parser

The model's parser: ECMA-262's grammars as data, decided by one exhaustive
search whose every node is checked against the grammar's derivation relation (`Ecma.Grammar.Derives`). It is the
accelerator of `Model.parse`. The grammar data is described in [GRAMMAR.md](GRAMMAR.md).

## Layers

- **`Ecma.Grammar`**: the grammars from spec.html's `emu-grammar` blocks
  (generated by `crates/jsgrammar`), and the executable notation (`applyArgs`,
  guards, `GL.alts` with the Annex B overlays and readings, `chainNt`,
  `unitNt`) that the derivation relation and the parser both read.
- **`Engine.Parse`** imports only Grammar. It is generic over a
  node-builder record (`Parse.Builder`: the node constructor, its views, and
  the code point classes `<USP>`, ID_Start and ID_Continue).
  - `Search.lean`: one exhaustive memoized search over GL's rules: top-down,
    one call per (nonterminal, parameters, position), all end positions, left
    recursion by seed growth, `but not` and `∉ N` from final entries. Over code
    points for the code point goals; over tokens for the syntactic goals.
  - `Lex.lean`: `lexAt` reads each token under the goal its expected terminal
    implies; the first under InputElementHashbangOrRegExp for a Script or
    Module goal only.
  - `Kernel.lean`: `mk` checks every node against `Ecma.Grammar.Derives`. A
    failed check is a stop (undecided), never a tree or "no parse".
  - `Code.lean`: the negative oracle `Code.dec` / `decAny`.
  - §12.10 by iteration: with no parse, the token after the furthest match is
    the offending token, and a virtual `;` goes before it where rule 1 or 2
    holds. A span two derivations share stops (`ambiguous`).
- **`Engine.Model.Parse`** instantiates it at the engine's Parse Nodes and is
  `Engine.parse`. An engine Parse Node is a GL tree: production id,
  nonterminal, parameters, code point span, children, text.

The parser implements no static semantics: early errors, "must cover",
CoveredBy and the lexical SDOs are rows that the machine runs over its
trees. A text the grammar derives gets a tree even when an early error rejects
it. Nesting depth past the bound is a host limit (undecided).

## The contract

`Model.parse` gives `some (some n)` (a Parse Node), `some none` (no parse,
only after a complete decision) or `none` (undecided: fuel, depth, a kernel
check, or ambiguity). `Model.ParseLaws`, `Model.CoverLaws`, and `Model.NodeLaws`
(`Ecma.Model.NodeRel`) state what a parse and a cover must be, and all three are
proved of `Engine.Impl` (`Engine.Claims.parseLaws`, `Engine.Claims.coverLaws`,
`Engine.Claims.nodeLaws`). `Derives` and `Covers` are `Ecma.Grammar`'s.

`Engine.Parse.parse` decides the syntactic goals over tokens, `JSONText` (`json`),
and the code point goals (lexical, numeric string, RegExp; under Annex B,
B.1.2's committed parse in two passes). `StringNumericLiteral` and
`StringIntegerLiteral` use the `parseNumeric` fast path verified by
`verifyCodeNode`, falling back to `Engine.Parse.parse`.
