The Spec: Algorithms

spec.html §7.1.4 ToNumber ( arg ) 
<emu-clause id="sec-tonumber" type="abstract operation">
  <h1>ToNumber ( _arg_: an ECMAScript language value ): either a normal completion containing a Number or a throw completion</h1>
  <emu-alg>
    1. If _arg_ is a Number, return _arg_.
    1. If _arg_ is either a Symbol or a BigInt, throw a *TypeError* exception.
    1. If _arg_ is *undefined*, return *NaN*.
    1. If _arg_ is either *null* or *false*, return *+0*<sub>𝔽</sub>.
    1. If _arg_ is *true*, return *1*<sub>𝔽</sub>.
    1. If _arg_ is a String, return StringToNumber(_arg_).
    1. Assert: _arg_ is an Object.
    1. Let _primitiveValue_ be ? ToPrimitive(_arg_, ~number~).
    1. Assert: _primitiveValue_ is not an Object.
    1. Return ? ToNumber(_primitiveValue_).
  </emu-alg>
</emu-clause>
spec/spectec/clauses/S07.spectec 0-diff splice with spec.html 
def @sec-tonumber "ToNumber"
  (kind ao params [arg : #"ECMAScript language value"] -> completion<Number> | #"throw completion")
  vars [arg, primitiveValue] {
  if arg is ty {Number} -> return arg
  if arg is ty {Symbol; BigInt} -> throw @ph-new-error([[TypeError]])
  if arg is val {undefined} -> return nan
  if arg is val {null; false} -> return num_f(+0)
  if arg is val {true} -> return num_f(1)
  if arg is ty {String} -> return @sec-stringtonumber(arg)
  assert arg is ty {Object}
  let primitiveValue = ? @sec-toprimitive(arg, ~number~)
  assert primitiveValue is not ty {Object}
  return ? @sec-tonumber(primitiveValue)
}

The Spec: Models

spec.html §5.2.6 Mathematical Operations & §6.1.6.1 The Number Type
“The Number type has exactly 18,437,736,874,454,810,627 (264 − 253 + 3) values, representing the double-precision floating point IEEE 754-2019 binary64 values… except that the distinct NaN values of the IEEE Standard are represented in ECMAScript as a single special NaN value… two other special values, +∞𝔽 and −∞𝔽… +0𝔽 and −0𝔽, and the finite non-zero values.”
How it translates Each specification sort (Math, Num, Str, Addr, Node, …) is an abstract carrier in syntax Model record, with a case view NumView(Math) and primitive operations — fixing no concrete representation.
spec/spectec/prose/01-model.spectec Abstract carriers & operations 
--- The case view of an IEEE 754-2019 binary64 Number value (§6.1.6.1).
syntax NumView (Math : Type) {
  | nan  | posInf  | negInf  | posZero  | negZero  | finite (m : Math)
}

--- A model of the specification's sorts and primitive operations (excerpt).
syntax Model record {
  Math : Type;          Num : Type;           Str : Type;
  Addr : Type;          Node : Type;          Heap : Type -> Type;

  numView : Num -> NumView(Math);             --- inspect binary64 value
  numOf   : Math -> Num;                      --- 𝔽(x): roundTiesToEven (§6.1.6.1)
  numAdd  : Num -> Num -> Num;                --- IEEE 754-2019 addition
  numNeg  : Num -> Num;                       --- unary negation
}

The Spec: Relations

spec.html §29.6.6 happens-before

For a candidate execution execution, its happens-before Relation is the least Relation on Memory events that satisfies the following — eventA happens-before eventB if any of the following conditions are true:

  • eventA is-agent-order-before eventB in execution.
  • eventA synchronizes-with eventB in execution.
  • SharedDataBlockEventSet(execution) contains both eventA and eventB, eventA.[[Order]] is ~init~, and eventA and eventB have overlapping memory ranges.
  • There is an event eventC such that eventA happens-before eventC and eventC happens-before eventB in execution.
How it translates “The least Relation that satisfies…” becomes an inductive SpecTec relation, with one Horn rule (conclusion :- premises;) per prose bullet.
spec/spectec/prose/07-memory-model.spectec Inductive SpecTec relation 
--- happens-before (§29.6.6): the least Relation closed under its four rules.
relation HB (rbf : Rbf(E)) (hsw : Rel(E)) : Rel(E) {
  rule agent {a b : E} :
    HB(rbf, hsw, a, b) :- agentOrder(x, a, b);
  rule sync  {a b : E} :
    HB(rbf, hsw, a, b) :- SyncWith(x, rbf, hsw, a, b);
  rule init  {a b : E} :
    HB(rbf, hsw, a, b) :- inSdb(x, a), inSdb(x, b), x.order(a) = .init, rangesOverlapping(x, a, b);
  rule trans {a b c : E} :
    HB(rbf, hsw, a, b) :- HB(rbf, hsw, a, c), HB(rbf, hsw, c, b);
}

The Spec: Laws

spec.html §6.1.6.1.1 Number::unaryMinus & §4.2 Hosts and Implementations
§6.1.6.1.1 Number::unaryMinus ( number ): “1. If number is NaN, return NaN. 2. Return the negation of number; that is, compute a Number with the same magnitude but opposite sign.”

How it translates Each prose requirement becomes a law in a SpecTec laws block (148 model, 7 parser & 72 host laws), quoting the governing spec.html sentence verbatim (checked by law_quotes.py).
spec/spectec/prose/05-model-laws.spectec & 24-host-laws-hooks.spectec Quotes verified against spec.html 
laws Model.NumLaws (M : Model) {
  --- sec-numeric-types-number-unaryMinus:
  --- "Return the negation of number; that is, compute a Number with the same magnitude but opposite sign."
  law numNeg_view : forall a, M.numView(M.numNeg(a)) = match M.numView(a) with
    | .nan => .nan        | .posInf => .negInf    | .posZero => .negZero
    | .negInf => .posInf  | .negZero => .posZero  | .finite(m) => .finite(M.neg(m))
  end;
}

laws Host.HookLaws (H : Host(M)) {
  --- sec-hosts-and-implementations:
  --- "A host hook must conform to at least the following requirements: It must return either a normal completion or a throw completion."
  law hookCompletion : forall c xs s r s',
    H.answers(c, xs, s, r, s') -> compType(r) = Known.eNormal \/ compType(r) = Known.eThrow;
}

Spec issues & errata

  • Contradictions & wrong results
    • Array.fromAsync() fulfills with undefined; CreateIntrinsics misaligns async
    • Timed-out Atomics.wait() returns "ok"; +0 * -5 yields +0; TLA using never disposes
  • Failing Assert:s on valid programs
    • Every await resumes AsyncBlockStart with ~empty~, failing its ~unused~ Assert:
    • /\p{Hex}/u, new Date(0).setHours(1e21) & diamond export * DAGs trip literal Assert:s
  • Missing grammar cases, type errors & §29 defects
    • Post-ASI /re/ lexing, new Function("o", "return o.#f") & return (f(x)) cover tail calls
    • "ab".split("") builds code units, not Strings; §29 RMW cycles, Races & block-aliasing bugs
  • In-flight proposal bugs
    • Missing BoundNames SDO row & [[DeferredNamespace]] slots in import defer
    • *undefined* vs. ~empty~ / ~unused~ mismatches in Immutable ArrayBuffers

What this can deliver

  • Invariants
    • §6.1.7.3 essential object invariants & module [[Status]] monotonicity
    • Proposal guarantees (e.g. immutable ArrayBuffer bytes never mutate)
  • Soundness
    • ! never throws, Assert:s never fail & slots/SDOs never miss a case
    • Editorial refactorings proved observably identical
    • Elided spec allocations & §29 reorderings proved unobservable
  • Generated JS reference VM
    • Executable engine & proved parser compiled from SpecTec & spec.html (native & Wasm)
    • Verified shortcuts & grammar kernel proved with 0 sorrys (Engine.implements, Engine.Claims.parseLaws)
