What it is to implement the specification

The downstream Lean conformance contract (§2) that bridges the compiled SpecTec specification to the concrete engine, together with the observable state, configuration and §5.2 identifier types in its transitive closure. What is proved reads it field by field.

What it is to implement the specification

From lean/Ecma/Implements.lean

An implementation has values (a Model), a host (a Host), algorithms of its own beside the specification's, and its own transition between the machine's configurations. It implements the specification (Implements) when its values obey the model's laws, its host obeys the host's laws, and each transition it takes from a configuration the specification's machine reaches is some transitions of that machine. Its every run is then a run of the specification's machine.

Both machines run under whether Asserts are checked.

Runs

From lean/Ecma/Machine/Run.lean

What it is for the specification's algorithms to run, over any model and host: a relation between configurations, with no bound. Step is one transition of the machine (step), Steps any number of them, and Runs a run that ends. Calls is a call's run from a state to its result. The specification's own context (Ctx.spec) has the program's code, the host, and whether Asserts are checked.

What it is for an implementation to be the specification's is stated over these (Ecma.Implements).

Configurations and calls

From lean/Ecma/Machine/Config.lean

The machine's state: a frame per call, its kind, Parse Node, slots, step path and continuations. The continuations are generic: a code sequence's rest (seq), an operand list and its use (args, the use a Fin), a short circuit's rest (junct), a List's elements under a type (all), a subject's binding (bind, read by Op.bound), a scoped call's return (scope), a loop's body and test (loop, test) and a table step's key test (tstep). A loop runs one control point (Phase) at a time: its iterator's state (IterSt) and rounds in a Loop. Every leaf operation runs the one leaf table (leaf) over the dispatch (subD).

Algorithm notation and specification identifiers (§5.2)

From lean/Ecma/Notation/Syntax.lean

A concrete syntax tree of spec.html's algorithm notation (§5.2), with semantic node kinds. crates/spec-gen emits it; Print prints it back byte for byte. Surface variants (Article, AltForm, …) are kept for printing and are ignored by the machine. Names are interned: every reference is a Nat into the declaration tables (Decls), except prose, string literals and attributes.

The tree is untyped and first-order. Sorts are checked separately against the parsed headers; the machine stops with a sort error on ill-sorted data.
