Three things to know first

  1. The Lean is generated where the English is algorithmic. Every algorithm step, table and early-error rule in lean/Ecma/Gen is produced from spec.html by a generator, never edited by hand. The generator checks that it prints each one back as the HTML's text; the Lean printer (scripts/bijection.py) checks the same from the Lean side.
  2. Where the English is not algorithmic, the Lean quotes it. What the text assumes (that mathematical values behave as the reals, that Numbers are IEEE 754 binary64) and what it leaves to the host (time, job scheduling, locale) is a law, and each law's documentation quotes the sentence it reads. A script checks every quotation against the pinned spec.html.
  3. The claim is precise and has limits. The engine is proved to implement the specification. The proof relies on Lean's {{axiom_count}} standard axioms alone ({{runtime_pins}} equations on the generated program are checked at run time before shortcuts run); the parser's laws are owed; the debugger is outside the claim. What is proved lists all of it.
