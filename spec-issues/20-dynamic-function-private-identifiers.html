20. new Function("o", "return o.#f"): no check of private names in dynamic functions

Location
§20.2.1.1.1 CreateDynamicFunction (#sec-createdynamicfunction), steps 18–29; §6.2.5.9 MakePrivateReference (#sec-makeprivatereference), step 2.
Kind
missing step (an early error that no goal of CreateDynamicFunction applies), and a failing Assert.
Model erratum
CreateDynamicFunctionPrivateIdentifiers, default reading proposed; its readings: literal, test262, proposed (the proposed reading is the Proposed wording; the test262 reading checks the body only).
Upstream
Checked 2026-11-19: none found (searched for "CreateDynamicFunction" with private, no hits, and "AllPrivateIdentifiersValid"). PR #1668 (merged 2021-05), which brought private names into the specification, has no check of them in CreateDynamicFunction. Issue #3080 (closed, 2023-05), "MakePrivateReference and ResolvePrivateIdentifier assert that outer private environment can't be null", asked why MakePrivateReference asserts a non-null PrivateEnvironment; the answer there points to AllPrivateIdentifiersValid's early errors, which are rules of Scripts, Modules and direct eval.
On this site
CreateDynamicFunctionPrivateIdentifiers on Spec issues & errata (defect of the text; SpecTec bakes in the proposed reading)

Text

AllPrivateIdentifiersValid is applied in three places:

§16.1.1 (ScriptBody): It is a Syntax Error if AllPrivateIdentifiersValid of StatementList with argument « » is false unless the source text containing ScriptBody is eval code that is being processed by a direct eval.

§16.2.1.1 (ModuleBody): It is a Syntax Error if AllPrivateIdentifiersValid of ModuleItemList with argument « » is false.

§19.2.1.4 EvalDeclarationInstantiation: If AllPrivateIdentifiersValid of body with argument privateIdentifiers is false, throw a SyntaxError exception.

CreateDynamicFunction parses with other goals and has no such step:

18. Let params be ParseText(joinedParamsString, paramGrammar).

19. If params is a List of errors, throw a SyntaxError exception.

20. Let body be ParseText(bodyParseString, bodyGrammar).

21. If body is a List of errors, throw a SyntaxError exception.

…

24. Let expr be ParseText(sourceText, exprGrammar).

25. If expr is a List of errors, throw a SyntaxError exception.

…

28. Let privateEnv be null.

29. Let func be OrdinaryFunctionCreate(funcProto, sourceText, params, body, non-lexical-this, envRecord, privateEnv).

MakePrivateReference:

1. Let privateEnv be the running execution context's PrivateEnvironment.

2. Assert: privateEnv is not null.

Problem

The goals of steps 18, 20 and 24 are FormalParameters, FunctionBody and FunctionExpression (or their generator and async forms). None of their early errors applies AllPrivateIdentifiersValid, so a body or a parameter list that uses o.#f outside any class parses without error, and step 29 creates a function whose [[PrivateEnvironment]] is null. Calling it evaluates o.#f, whose MakePrivateReference finds that null PrivateEnvironment: the Assert of step 2 fails. The parameters reach it too, through an initializer (new Function("a = {}.#g", ""), called with no argument).

The model's default reading is the proposed wording, which checks both, as the engines do; its test262 reading checks the body only, which is what test262 tests. Where a function is created, calling it (new Function("o", "return o.#f")({}) under the literal reading, new Function("a = {}.#g", "")() under the literal and test262 readings) stops the model with stop: sortError sec-resolve-private-identifier#0 1: the null PrivateEnvironment of MakePrivateReference's step 2 is passed on to ResolvePrivateIdentifier (#sec-resolve-private-identifier), whose parameter is a PrivateEnvironment Record.

test262

built-ins/Function/private-identifiers-not-empty.js requires a SyntaxError for new Function("o.#f"); its info quotes the class fields proposal's steps of CreateDynamicFunction:

30. If AllPrivateIdentifiersValid of body with the argument privateIdentifiers is false, throw a SyntaxError exception.

31. If AllPrivateIdentifiersValid of parameters with the argument privateIdentifiers is false, throw a SyntaxError exception.

Under the literal text it fails. staging/sm/PrivateName/lexical-presence.js also requires a SyntaxError from Function(str) for bodies. No test covers the parameters.
