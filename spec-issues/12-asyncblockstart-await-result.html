12. AsyncBlockStart asserts unused, but Await resumes it with empty

Location
§27.10.5.2 AsyncBlockStart (#sec-asyncblockstart), steps 3–4, against §27.10.5.3 Await (#await), step 8, and §9.4.8 RunCallerContext (#sec-runcallercontext), step 4; §9.4.7 RunSuspendedContext (#sec-runsuspendedcontext), its return type.
Kind
failing Assert (in every async function that awaits).
Model erratum
AsyncBlockStartAwaitResult, default reading test262; its readings: literal, test262, proposed (the test262 and proposed readings are one: the Assert of Proposed wording); the literal reading stops at AsyncBlockStart step 4.
Upstream

Text

AsyncBlockStart:

1. Let closure be a new Abstract Closure with no parameters that captures promiseCapability and asyncBody and performs the following steps when called:

…

j. Resume callerContext, passing NormalCompletion(unused).

2. Set the code evaluation state of asyncContext such that …

3. Let result be ! RunSuspendedContext(asyncContext, NormalCompletion(empty)).

4. Assert: result is unused.

5. NOTE: The possible sources of result values are Await or, if the async function doesn't await anything, step … above.

Await:

8. Return ? RunCallerContext(empty).

RunCallerContext (value: an ECMAScript language value or empty):

4. Resume callerContext, passing NormalCompletion(value).

Step 5's "step … above" is step 1.j. RunSuspendedContext returns "either a normal completion containing either an ECMAScript language value or unused, or an abrupt completion".

Problem

The first await in an async function body runs Await step 8, which resumes the caller context with NormalCompletion(empty). That caller is AsyncBlockStart step 3, so result is empty and step 4's Assert fails. Every async function or module body that awaits before it returns reaches it. The same empty is also outside RunSuspendedContext's return type, here and in §27.9.3.6 AsyncGeneratorResume step 4 (an async generator that awaits).

The two sides can be made to agree in two ways. Await could pass unused, but RunCallerContext's value parameter is "an ECMAScript language value or empty", and Await is its only caller that passes a value that is not a language value, so that parameter would change too. Or AsyncBlockStart could accept empty, which needs only its Assert and RunSuspendedContext's return type, which an async generator's await also reaches (AsyncGeneratorResume step 4). The proposed wording below is the second; the model's test262 reading runs under its Assert.

Examples

examples/12-asyncblockstart-await-result.js (outputs: the recorded runs):

async function f() { await 1; return 2; }
f().then(function (v) { print("f fulfilled with " + v); });
output
literal text the Assert of AsyncBlockStart step 4 fails at await 1
V8, SpiderMonkey, JavaScriptCore f fulfilled with 2
formal model (literal reading) stops at AsyncBlockStart step 4 (stop: erratum AsyncBlockStartAwaitResult sec-asyncblockstart#0 4)
formal model (test262 and proposed readings) f fulfilled with 2

test262

Every test of an async function that awaits reaches the Assert; an Assert has no observable effect, so none fails.

The program
