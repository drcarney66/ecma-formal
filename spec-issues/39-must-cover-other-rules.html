39. Early error rules read "the |n| that is covered by" a cover that covers nothing

Location
§5.1.5 The Syntactic Grammar (#sec-syntactic-grammar), the definition of "must cover", its item 4; with the early errors of §15.3.1 ArrowFunction (#sec-arrow-function-definitions-static-semantics-early-errors) and §15.9.1 AsyncArrowFunction (#sec-async-arrow-function-definitions-static-semantics-early-errors), and the covered-node steps of §8.5.1 Contains (#sec-static-semantics-contains), §8.2.1 BoundNames (#sec-static-semantics-boundnames) and §15.1.3 IsSimpleParameterList (#sec-static-semantics-issimpleparameterlist).
Kind
undefined value (a rule's condition names a Parse Node that does not exist); every reading gives the same verdict, a SyntaxError.
Model erratum
MustCoverEarlyErrorOrder, baked-in SpecTec reading test262 (spec/spectec/clauses/Helpers.spectec, @formal-earlyerrorsof; lean/Ecma/Lower/LinEarly.lean, linOwn and linTree). Without ordering, sibling and ancestor early-error rules read "the |n| that is covered by _p_" on a failed cover and stop on a missing Parse Node; SpecTec evaluates non-covered children bottom-up before parent rules and runs a production's "must cover" rules before its other rules.
Upstream

Text

§5.1.5 defines "p must cover an n" by a list of four items (item 3 with two sub-items), quoted here in order:

No early error rules are applied to p or any of its descendants.

The sequence of tokens originally matched by p is parsed again using n as the goal symbol. …

If the sequence of tokens can be parsed as a single instance of n, with no tokens left over, then:

We refer to that instance of n (a Parse Node, unique for a given p) as “the n that is covered by p”.

Early error rules are applied to the n that is covered by p and to its descendants, …

Otherwise (if the parse fails), it is an early Syntax Error.

The rule is one of a production above p, beside rules that look through p:

ArrowFunction : ArrowParameters => ConciseBody

It is a Syntax Error if ArrowParameters Contains YieldExpression is true.

…

ArrowParameters : CoverParenthesizedExpressionAndArrowParameterList

CoverParenthesizedExpressionAndArrowParameterList must cover an ArrowFormalParameters.

AsyncArrowFunction : CoverCallExpressionAndAsyncArrowHead => AsyncConciseBody

CoverCallExpressionAndAsyncArrowHead must cover an AsyncArrowHead.

It is a Syntax Error if any element of the BoundNames of CoverCallExpressionAndAsyncArrowHead also occurs in the LexicallyDeclaredNames of AsyncConciseBody.

Contains, BoundNames and IsSimpleParameterList at these covers begin with "Let formals be the |ArrowFormalParameters| that is covered by |CoverParenthesizedExpressionAndArrowParameterList|." or "Let head be the |AsyncArrowHead| that is covered by |CoverCallExpressionAndAsyncArrowHead|." The rules of §16.1.1 that a Script's |StatementList| not Contain super or |NewTarget| reach every arrow function of the Script the same way.

Problem

When the reparse of item 2 fails there is no "n that is covered by p", so the conditions above refer to nothing, and their steps have no result. Item 1 stops rules from applying to p and below it, not to the productions above it. §5.2.5 asks an implementation to "validate all of the early error rules of the productions used to parse" the source, and §11.1.6 ParseText, step 2, to "analyse the parse result for any early error conditions"; neither says that a rule whose condition cannot be evaluated is skipped, nor in what order the rules are evaluated. The verdict is not in doubt, since item 4 is itself an early error, but a reader evaluating the rules as written meets an undefined step before reaching it.

test262

The SyntaxErrors are required by language/expressions/arrow-function/dstr/{,dflt-}ary-ptrn-rest-{init,not-final}-*.js, language/expressions/async-arrow-function/{dflt-params-rest,early-errors-arrow-formals-lineterminator,rest-params-trailing-comma-early-error}.js and their siblings in the other function forms; every reading that reaches item 4 passes them.

The program

The example is a Script. Its runs on the engines and on the model: the examples' runs.

Source examples/39-must-cover-other-rules.js
// Each source has a cover that does not cover what an early error rule says it must; the
// other rules of the same and enclosing productions read static semantics through the cover.
if (typeof print === "undefined") globalThis.print = console.log;
var sources = [
  "([...x = []]) => {};",
  "([...x, y]) => {};",
  "(a, ...b,) => {};",
  "async (...x = []) => {};",
  "async\n(foo) => {};",
  "(x) => {};",
];
for (var s of sources) {
  try {
    (0, eval)(s);
    print(JSON.stringify(s) + ": no error");
  } catch (e) {
    print(JSON.stringify(s) + ": " + e.constructor.name);
  }
}
