37. String.prototype.split with an empty separator builds an Array of code units

Location
§22.1.3.23 String.prototype.split (#sec-string.prototype.split), steps 10.d–e and the method's description, against §7.3.17 CreateArrayFromList (#sec-createarrayfromlist), its parameter.
Kind
type error (a List of code units where a List of ECMAScript language values is required).
Model erratum
SplitCodeUnitStrings, default reading test262; its readings: literal, test262, proposed. The test262 and proposed readings are the same steps, the proposed wording below.
Upstream
Checked 2026-11-19: none found (searched for split with "empty separator" and with "code units"). On this site
SplitCodeUnitStrings on Spec issues & errata (defect of the text; SpecTec bakes in the test262 reading)

Text

10. If separatorLength = 0, then

a. Let stringLength be the length of string.

b. Let outLength be the result of clamping substringLimitInt between 0 and stringLength.

c. Let head be the substring of string from 0 to outLength.

d. Let codeUnits be a List consisting of the sequence of code units that are the elements of head.

e. Return CreateArrayFromList(codeUnits).

CreateArrayFromList takes "elements: a List of ECMAScript language values", and the method's description says: "This method finds substrings separated by separator in its this value and returns them in an Array, … any separator coerced to the empty String splits the this value into individual code units, …".

Problem

A code unit is one of the 16-bit unsigned integer values a String is a sequence of (§6.1.4), not an ECMAScript language value. Step 10.e passes a List of them to CreateArrayFromList, outside its parameter's type, and the Array it would build has elements that are not values: typeof "ab".split("")[1] has no defined result. The description states the intent, substrings in an Array, here one String of one code unit per element, which step 10.d does not say.

Proposed wording

--- a/spec.html
+++ b/spec.html
@@ -36559,7 +36559,9 @@
             1. Let _stringLength_ be the length of _string_.
             1. Let _outLength_ be the result of clamping _substringLimitInt_ between 0 and _stringLength_.
             1. Let _head_ be the substring of _string_ from 0 to _outLength_.
-            1. Let _codeUnits_ be a List consisting of the sequence of code units that are the elements of _head_.
+            1. Let _codeUnits_ be a new empty List.
+            1. For each integer _i_ such that 0 ≤ _i_ &lt; _outLength_, in ascending order, do
+              1. Append the substring of _head_ from _i_ to _i_ + 1 to _codeUnits_.
             1. Return CreateArrayFromList(_codeUnits_).
           1. If _string_ is the empty String, return CreateArrayFromList(« _string_ »).
           1. Let _substrings_ be a new empty List.

test262

built-ins/String/prototype/split/separator-empty-string-instance-is-string.js requires new String(" ").split("")[0] to be " "; seven more test files (three in the same directory, RegExp/escape/not-escaped.js, Iterator/zipKeyed/padding-iteration.js and two in staging/sm/String) and the harness's iteratorZipUtils.js use the elements of a split("") as Strings. All of them fail, or have no defined result, under the literal step.
