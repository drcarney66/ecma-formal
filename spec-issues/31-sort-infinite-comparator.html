31. Sort: a comparator that returns ±∞ is neither consistent nor inconsistent

Location
§23.1.3.30.1 SortIndexedProperties (#sec-sortindexedproperties), the sort order conditions and the definition of a consistent comparator after its algorithm, with §23.1.3.30.2 CompareArrayElements (#sec-comparearrayelements), step 4.a, §23.2.4.8 CompareTypedArrayElements (#sec-comparetypedarrayelements), step 2.a, and §5.2.6 Mathematical Operations (#sec-mathematical-operations).
Kind
an undefined value (ℝ of a non-finite Number) in a definition.
Model erratum
SortInfiniteComparator, default reading test262; its readings: literal, test262, proposed. Read literally, a ±∞ result stops the run (ℝ has no value); the test262 and proposed readings take no ℝ, so the order is the host's, and the model's hosts order by the sign of the result.
Upstream
Checked 2026-11-19: none found (searched for "consistent comparator" and for comparator with Infinity). Issue #3172 (open, 2023-09), "Call SortCompare only on actual elements", is about which values SortCompare is called on.
On this site
SortInfiniteComparator on Spec issues & errata (defect of the text; SpecTec bakes in the test262 reading)

Text

The definition of a consistent comparator:

The notation a <C b means ℝ(comparator(a, b)) < 0; a =C b means ℝ(comparator(a, b)) = 0; and a >C b means ℝ(comparator(a, b)) > 0.

Calling comparator(a, b) always returns the same value v when given a specific pair of values a and b as its two arguments. Furthermore, v is a Number, and v is not NaN. Note that this implies that exactly one of a <C b, a =C b, and a >C b will be true for a given pair of a and b.

The sort order conditions: "if ℝ(sortCompare(old[j], old[k])) < 0, then π(j) < π(k)" and "if ℝ(sortCompare(old[j], old[k])) = 0, then π(j) < π(k)". CompareArrayElements 4.a–4.c:

a. Let result be ? ToNumber(? Call(comparator, undefined, « x, y »)).

b. If result is NaN, return +0𝔽.

c. Return result.

§5.2.6: "The mathematical value of non-finite values is not defined."

Problem

A user comparator's result reaches the definition through ToNumber, with only NaN mapped to +0𝔽, so +∞𝔽 and -∞𝔽 reach it. For them ℝ is not defined, so none of <C, =C, >C has a value, and the "Note that this implies" sentence is false: the result is a Number and not NaN, yet the trichotomy fails. Whether (a, b) => a < b ? -Infinity : a > b ? Infinity : 0 is a consistent comparator, and so whether the sort order is fixed or implementation-defined, is not decided by the text; the two sort order conditions have the same gap. Every engine orders by the sign, as for finite results. Comparing the Number with +0𝔽 (§5.2.6: on Numbers, the operators are IEEE 754-2019's, so -0𝔽 = +0𝔽) gives every non-NaN Number a value and changes nothing for finite results.

Examples

examples/31-sort-infinite-comparator.js (outputs: the recorded runs):

print([3, 1, 2].sort((a, b) => a < b ? -Infinity : a > b ? Infinity : 0).join());
print([5, 3, 4, 1, 2].sort((a, b) => (a - b) * Infinity).join());
print(["b", "a", "c"].sort((a, b) => a < b ? -Infinity : a > b ? Infinity : 0).join());
output

proposed text 1,2,3, 1,2,3,4,5, a,b,c
V8, SpiderMonkey, JavaScriptCore 1,2,3, 1,2,3,4,5, a,b,c
formal model, literal reading none: the run stops at the first ±∞ result
formal model, test262 and proposed readings 1,2,3, 1,2,3,4,5, a,b,c

test262

None found: the sort tests use ±∞ as elements, not as comparator results. A test that sorts with the first comparator above and expects 1,2,3 passes on every engine tried and holds only under the proposed text.

The program

The example is a Script. Its runs on the engines and on the model: the examples' runs.

Source examples/31-sort-infinite-comparator.js
// SortIndexedProperties: a <C b means ℝ(comparator(a, b)) < 0, and ℝ(±∞) is not defined, so a comparator
// that returns ±∞ is neither consistent nor inconsistent by the definition.
if (typeof print === "undefined") globalThis.print = console.log;
print([3, 1, 2].sort((a, b) => a < b ? -Infinity : a > b ? Infinity : 0).join());
print([5, 3, 4, 1, 2].sort((a, b) => (a - b) * Infinity).join());
print(["b", "a", "c"].sort((a, b) => a < b ? -Infinity : a > b ? Infinity : 0).join());
