33. CreateIntrinsics passes async in prefix's position: every built-in gets a Boolean prefix

Location
§9.3.2 CreateIntrinsics (#sec-createintrinsics), step 2, with §10.3.4 CreateBuiltinFunction (#sec-createbuiltinfunction), its header and steps 3, 7 and 13, §10.2.9 SetFunctionName (#sec-setfunctionname), step 5.a, and the "name" paragraphs of §18 ECMAScript Standard Built-in Objects (#sec-ecmascript-standard-built-in-objects).
Kind
a call outside its parameter types (an argument in the wrong position).
Model erratum
CreateIntrinsicsAsyncArgument, default reading test262; its readings: literal, test262, proposed. Read literally, the run stops at SetFunctionName step 5.a under CreateBuiltinFunction, where async is concatenated as the prefix; the test262 and proposed readings pass prefix as §18 gives it and set [[Async]] from the step's sentence.
Upstream
Checked 2026-11-19: issue #3534 (open, 2025-02), "CreateIntrinsics isn't passing prefix to CreateBuiltinFunction for builtin getters/setters", reports the missing prefix; issue #4046 (open, 2026-10), "Editorial: CreateBuiltinFunction call in CreateIntrinsics passes wrong parameters", reports the argument position. PR #4022 (closed without merging, 2026-10) proposed six arguments and setting [[Async]] afterwards; PR #2833 (open, 2022-07), "Editorial: Specify prefix for non-specific uses of CreateBuiltinFunction", passes prefix last and predates async, which came with PR #2942 (merged 2025-12, commit 7029ed1b2).
On this site
CreateIntrinsicsAsyncArgument on Spec issues & errata (defect of the text; SpecTec bakes in the test262 reading)

Text

CreateIntrinsics, step 2:

All values that are built-in function objects are created by performing CreateBuiltinFunction(steps, length, name, slots, realmRecord, proto, async) where steps is the definition of that function provided by this specification, name is the initial value of the function's "name" property, … and async is true if the function is described as “async” and false otherwise.

CreateBuiltinFunction's header:

CreateBuiltinFunction ( behaviour: an Abstract Closure, a set of algorithm steps, or some other definition of a function's behaviour provided in this specification, length: a non-negative integer or +∞, name: a property key or a Private Name, additionalInternalSlotsList: a List of names of internal slots, optional realm: a Realm Record, optional proto: an Object or null, optional prefix: a String, optional async: a Boolean, ): a built-in function object

and its steps:

3. If async is not present, set async to false.

7. Set func.[[Async]] to async.

13. If prefix is not present, then

a. Perform SetFunctionName(func, name).

14. Else,

a. Perform SetFunctionName(func, name, prefix).

SetFunctionName:

5. If prefix is present, then

a. Let prefixedName be the string-concatenation of prefix, the code unit 0x0020 (SPACE), and name.

Problem

The step passes seven arguments; the seventh parameter is prefix, a String. So every built-in function created by CreateIntrinsics gets prefix false (or true) and no async. CreateBuiltinFunction then calls SetFunctionName with a Boolean prefix, whose step 5.a concatenates a Boolean with Strings, which is not defined; and [[Async]] is false for every built-in, so Array.fromAsync, the one built-in described as "async", runs its steps without AsyncFunctionStart (BuiltinCallOrConstruct, step 10) and its Await has no async function context. The step's intent is clear from its own sentence and from §18: async in its own position, and prefix "get" or "set" for an accessor, which the step does not pass at all. Since async follows prefix, a call that passes async must pass some prefix, so the fix gives prefix an empty case.

Examples

examples/33-createintrinsics-async-argument-position.js (outputs: the recorded runs):

print(Object.getOwnPropertyDescriptor(Map.prototype, "size").get.name);
print(Object.getOwnPropertyDescriptor(RegExp.prototype, "flags").get.name);
var p = Array.fromAsync([1, 2]);
print(Object.prototype.toString.call(p));
p.then(function (v) { print("fromAsync fulfils with " + JSON.stringify(v)); });
output
literal text none: creating the realm's first built-in function concatenates a Boolean (SetFunctionName 5.a)
proposed text get size, get flags, [object Promise], fromAsync fulfils with [1,2]
V8, SpiderMonkey, JavaScriptCore get size, get flags, [object Promise], fromAsync fulfils with [1,2]
formal model, literal reading none: the run stops at SetFunctionName 5.a while the realm is created
formal model, test262 and proposed readings get size, get flags, [object Promise], fromAsync fulfils with [1,2]

test262

Every test needs the realm's built-ins. Those that observe the two arguments: built-ins/Array/fromAsync/returns-promise.js and built-ins/Array/fromAsync/asyncitems-null-undefined.js (a rejected promise, not a synchronous throw) need [[Async]] true; built-ins/Map/prototype/size/name.js and the other accessor name.js tests need the "get " prefix.
