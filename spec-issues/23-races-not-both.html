23. Races: "it is not the case that both" is always true

Location
§29.8 Races (#sec-races), step 1.a; §29.7.5 Valid Executions (#sec-valid-executions); §29.10 Data Race Freedom (#sec-data-race-freedom).
Kind
a condition that is always true under the clause's own definitions.
Model erratum
RacesNotBoth, baked-in SpecTec reading literal (Ecma.MemoryModel.Race, spec/spectec/prose/07-memory-model.spectec); its note in site/errata.json gives the proposed wording below.
Upstream
Checked 2026-11-19: PR #4021 (closed without merging, 2026-10), "Normative: exclude happens-before ordered events from races", proposed requiring that neither event happens-before the other; no issue was found (searched for "not the case that both" and "Races"). The wording came with PR #3321 (merged 2024-05, commit 1babaf809), "Editorial: Rework memory model relations", which replaced "If the pairs (E, D) and (D, E) are not in execution.[[HappensBefore]]".
On this site
RacesNotBoth on Spec issues & errata (defect of the text; SpecTec bakes in the literal text)

Text

1. If eventA and eventB are not the same Shared Data Block event, then

a. If it is not the case that both eventA happens-before eventB in execution and eventB happens-before eventA in execution, then

i. If eventA is either a WriteSharedMemory or ReadModifyWriteSharedMemory event, eventB is either a WriteSharedMemory or ReadModifyWriteSharedMemory event, and eventA and eventB do not have disjoint memory ranges, then

1. Return true.

ii. If eventA reads-from eventB in execution or eventB reads-from eventA in execution, then

1. Return true.

2. Return false.

§29.7.5:

A candidate execution execution is a valid execution (or simply an execution) if all of the following are true.

…

execution admits a happens-before Relation that is a strict partial order.

§29.10:

The memory model guarantees sequential consistency of all events for data race free programs.

Problem

Races are defined for an execution, whose happens-before is a strict partial order, hence asymmetric: "eventA happens-before eventB and eventB happens-before eventA" never holds, and step 1.a's condition is always true. Read literally, any two conflicting events race, including two writes that happens-before orders, such as two writes of one agent in agent order. Data races, and with them the guarantee of §29.10, then cover every program that writes shared memory twice at the same bytes. The intent is that neither event happens-before the other.

Examples

None run: the definition is not observable through an engine, and the formal model defines the memory model in Lean but does not run it. Under the literal text, this single-agent program has a data race (two unordered writes of the same bytes, ordered by agent order), so it is not data race free:

const ta = new Int32Array(new SharedArrayBuffer(4));
ta[0] = 1;
ta[0] = 2;
